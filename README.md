# Портфолио Артёма Кашкарова

Сайт-портфолио продуктового дизайнера: главная с работами, страницы «Обо мне» и «Резюме», и отдельная страница на каждый кейс. Два языка, английский и русский, переключаются кнопкой в шапке. Визуальная основа — макет в Figma, поведение близко к шаблону [Tabfolio](https://tabfolio.framer.ai/): липкая навигация, появление блоков по мере прокрутки, карусели и аккордеон внутри кейса.

Это статический сайт без сервера и базы. Сборка отдаёт HTML, JS и картинки. Текст и состав страниц лежат в одном файле данных, вёрстка только его читает.

## Задача

Нужен был не конструктор страниц и не блог, а фиксированный набор экранов с одним и тем же каркасом:

- три постоянные страницы и кейсы, которые устроены одинаково: шапка, факты, аккордеон, секции с текстом и картинками;
- весь видимый текст на двух языках;
- правки вроде «поменять абзац» или «добавить работу» без правки компонентов;
- картинки, порядок проектов и скрытые секции тоже задаются данными.

Страницы не собираются из произвольной вёрстки. Меняется наполнение, а не набор блоков на каждом экране.

## Стек

| | |
| --- | --- |
| UI | React 19 |
| Язык | TypeScript |
| Сборка | Vite |
| Маршруты | TanStack Router, файлы в `src/routes` |
| Стили | обычный CSS в `src/styles.css` |
| Шрифт | Manrope |
| Проверка данных | Vitest, `src/data/site.contract.test.ts` |

React, TypeScript и Vite были исходным стеком проекта. TanStack Router добавлен файловыми маршрутами: адрес страницы совпадает с файлом, отдельный конфиг роутера не нужен. Серверного рендера нет: портфолио небольшое, его можно отдать как статику.

Стили написаны вручную, без Tailwind. Макет узкий и уже собран своими отступами, стеклом шапки и сетками. Утилитарный CSS здесь дублировал бы токены, а не экономил работу.

В макете стоит шрифт Involve. На сайт подключён Manrope с Google Fonts: у него есть кириллица, и оба языка рисуются одним семейством. Кириллические начертания подгружаются заранее, чтобы первая смена языка на русский не меняла ширину текста.

## Почему JSON, а не XML и не файлы страниц

Контент — это дерево объектов: профиль, навигация, проекты, секции, слайды. Компоненты ждут именно такой объект. `src/data/site.json` Vite импортирует как модуль, форма описана в `src/data/types.ts`, а `src/data/localize.ts` перед отрисовкой оставляет у каждого текста одну строку выбранного языка.

XML для этого дерева хуже. Те же вложенные секции, пары языков и списки слайдов превращаются в длинную разметку с тегами, а браузеру всё равно нужен разбор в объект, который React уже умеет получить из JSON без библиотеки. Схема при этом живёт второй раз, в XSD или в ручном парсере, хотя рядом уже есть типы TypeScript и тест контракта.

Отдельные форматы под документы тоже не подходят под эту задачу.

- **YAML** приятнее править руками, но это ещё один парсер и ошибки из-за отступов. Выигрыша в модели данных нет: структура та же.
- **MDX или Markdown** уместны, когда страница — статья со своей вёрсткой внутри текста. Здесь у всех кейсов один каркас, а отличия — это поля вроде заголовка, абзацев и картинок. Разметка внутри абзаца не нужна.
- **Astro или другой генератор с коллекциями** имел бы смысл, если бы сайт был набором документов со сборкой страниц из файлов. Сейчас страницы уже есть как React-маршруты, и второй слой сборки контента их повторил бы.

Ограничение честное: весь `site.json` попадает в клиентский бандл, включая оба языка. Для портфолио из нескольких кейсов это нормально. Если работ станет много, файл можно разрезать на модули, не меняя форму данных. Отдельная схема вроде Zod возможна позже; сейчас форму держат типы и `npm test`.

## Как это собрано

`src/main.tsx` поднимает язык и роутер. Корень в `src/routes/__root.tsx` рисует шапку, страницу и подвал. На кейсе шапка другая: назад к работам, якоря секций и язык.

| Адрес | Файл | Откуда данные |
| --- | --- | --- |
| `/` | `src/routes/index.tsx` | `projects`, сверху более новый год |
| `/about` | `src/routes/about.tsx` | `about` |
| `/resume` | `src/routes/resume.tsx` | `resume` |
| `/case-studies/<slug>` | `src/routes/case-studies/$slug.tsx` | один объект из `projects` |
| `/experiments` | `src/routes/experiments.tsx` | `experiments`, в меню пункт не выведен |

Картинки лежат в `src/assets`. В данных на них ссылаются как на `assets/имя-файла.png`.

## Запуск

```bash
npm install
npm run dev
```

Сборка — `npm run build`, проверка данных — `npm test`.

## Публикация

Сайт публикуется на GitHub Pages: https://ivanmochalov.github.io/designers-portfolio/

Выкладка запускается, когда в репозиторий попадает тег:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Для этой сборки у Vite базовый путь `/designers-portfolio/`. Локально `npm run dev` и обычный `npm run build` по-прежнему открываются с корня сайта.

Как править тексты, картинки и кейсы: [docs/content.md](docs/content.md).
